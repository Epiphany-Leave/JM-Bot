# 独立 JM-Bot 的交付决策

## rc.5 信息查询与管理页整理

新增 `/jm-s <ID>`，复用 `jmcomic` 的本子信息接口，只回复标题、作者、简介等文字，不请求图片或生成 PDF。查询与下载使用相同的授权、单任务限制、后台线程、网络方式和超时控制；信息缺失时明确显示“未提供”，不使用库的默认作者作为真实作者。网页将信息查询标为查询任务，避免显示图片下载进度。

管理页借鉴 AstrBot 的侧栏、顶栏、卡片和浅色主题，继续使用随镜像打包的 HTML/CSS/JavaScript，不引入其框架或外部资源。参考：[FullLayout.vue](https://github.com/AstrBotDevs/AstrBot/blob/master/dashboard/src/layouts/full/FullLayout.vue)、[LightTheme.ts](https://github.com/AstrBotDevs/AstrBot/blob/master/dashboard/src/theme/LightTheme.ts)。

README 面向首次使用者，只保留安装、网页设置、命令和必要排错；升级、备份、恢复等维护内容移至独立文档，部署包同时包含维护说明和验证记录，避免离线阅读时链接失效。

rc.5 通过本轮代码、浏览器、容器和匿名拉取检查前，不沿用 rc.4 的发布结论；真实 QQ 与用户下载源仍需现场验收。

## 既有部署与运行决策

统一管理页让用户只填一个 `ADMIN_PASSWORD`，在同一网页完成 QQ、权限、文件测试和下载设置。rc.4 保留 rc.3 的下载控制与内置代理，改进跨平台部署、订阅获取和错误提示。部署目标是支持 Docker Linux 容器的 x86-64 主机；Linux 使用 Engine 与 Compose，Windows 推荐 Docker Desktop 的 WSL 2 后端。原有 AstrBot 可继续独立运行，无需为本项目在宿主机安装 Python、VPN GUI 或 Clash Verge。rc.4 已发布并通过 Linux、真实 Mihomo、浏览器和匿名拉取检查；Windows Docker Desktop 及用户现场仍未实机验收，旧版本检查不代替本版验收。

| 决策 | 原因与边界 |
| --- | --- |
| 一个项目、三个容器 | 一次 Compose 启动即可运行；JM-Bot 提供网页和下载，NapCat 连接 QQ，Mihomo 处理可选代理；各自保留启动、日志、版本和网络边界，无需模型或额外数据库 |
| 自动创建五个数据目录 | 保持短格式 bind 挂载和原有五个相对路径；Docker 自动创建缺失目录，避免初装逐个建目录，也不要求旧用户迁移数据 |
| 仅映射 `16099:8080` | NapCat 6099、OneBot 3001、Mihomo 控制和代理端口不发布到宿主机 |
| 默认网络加独立 `proxy` 网络 | JM-Bot 与 NapCat 使用默认网络，JM-Bot 与 Mihomo 使用代理网络，NapCat 不加入后者；不设置 QQ 或宿主机全局代理 |
| 不使用 TUN、主机网络、Docker socket | 不接管宿主网络，不授予代理管理 Docker 的能力 |
| 网页先健康，外部服务再启动 | JM-Bot 预写内部配置；网页健康不依赖 QQ 登录或代理联网，避免循环等待 |
| 一个用户管理密码 | 至少 12 字符；内部 OneBot、代理认证和控制口令自动生成并持久化，无第二个密码或手动 token |
| 五个目录持久化 | `data`、`napcat-config`、`qq-data`、`downloads`、`proxy-data`；配置和代理目录含私密口令与节点，备份不公开 |
| rc.3 到 rc.4 原地升级 | 完整替换 Compose 并拉取重建；保留密码、原端口和五目录，不新增迁移目录；回退也保留数据并恢复旧 Compose |
| 指定群默认全员可用 | 只有已选群生效；可改为群号和用户同时授权，私聊始终检查用户；空名单拒绝对应请求 |
| 权限热保存，网络设置空闲保存 | 白名单保存后对后续调用立即生效；下载设置和代理操作不能改变执行中任务的网络 |
| 默认直连，代理须显式保存 | 导入并测试连接后再切换并保存 Mihomo 模式；检测使用已保存模式，代理故障不静默回退直连 |
| 程序拥有 Mihomo 配置 | Clash YAML 仅保留节点；原端口、控制器、TUN、规则不生效；其他格式由核心原生解析，无外部转换服务 |
| 链接或文件导入，最大 2 MiB | 链接使用固定 Mihomo User-Agent；先直连一次，失败且有成功保存的旧节点才验证旧代理并经它重试一次；没有节点可先上传 `.yaml`、`.yml`、`.txt`；文件无更新链接时重新上传，不承诺所有 VPN 格式 |
| 节点事务式应用 | 核心接受且实际连接探测成功才保存；失败保留之前持久化配置；冷重启后重新验证健康 |
| 固定 NapCat 与 Mihomo 版本 | NapCat `v4.18.42`、Mihomo `v1.19.33` 保持不变；JM-Bot 与 Mihomo 固定 `linux/amd64`，匹配目标 x86-64 Linux/Windows Linux 容器环境 |
| 全局单任务，无队列和跨任务续传 | 下载、合成、上传共用任务槽；重启不续传，上传未确认不自动重发 |
| 完整图片清单才合成 PDF | 缺页、损坏、停止或失败不发半本；清理失败任务图片，仅已生成但发送未确认的 PDF 留存 |
| 停止是协作式退出 | 网络阶段可停止，PDF 合成和上传不提供停止；底层请求及线程结束后才释放槽位，无硬 I/O 中断保证 |
| 任务目录 0755、PDF 0644 | NapCat UID/GID1000 可读取；宿主机目录写权限、ACL 与文件共享仍需实际发送 PDF 验证，不使用 chmod 777 |

少操作通过一个 Compose 项目、自动目录和单一网页实现。合为单容器仍需运行 QQ、下载器和代理进程，不能据此保证更少内存、CPU 或磁盘开销，还需增加进程启停、故障恢复和日志管理。[Docker 官方建议按服务划分容器](https://docs.docker.com/engine/containers/multi-service_container/)，并通过网络和共享目录协作；本项目继续采用三个服务。资源比较应测量三个服务整体的空闲和任务峰值，不把容器数量当作资源结论。

部署说明分别链接 [Docker Engine](https://docs.docker.com/engine/install/) 和 [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/)，网页设置共用。保留[短格式 bind 挂载自动创建宿主目录](https://docs.docker.com/reference/compose-file/services/#short-syntax-5)的行为，项目目录必须有写权限。运行文件位置以项目目录为准，不绑定某个厂商系统或用户绝对路径；UGOS 仅作为兼容 Compose 管理界面的 FAQ。

订阅获取与漫画下载的线路选择分开：固定 `mihomo/1.19.33` User-Agent，直连最多 20 秒一次；直连失败且有已保存节点时，旧代理验证最多 20 秒，通过后代理获取最多 20 秒一次，流程总预算 60 秒。失败显示安全的阶段、HTTP 状态或 DNS/TLS/连接/超时等具体原因与下一步建议，保留旧配置，不输出敏感链接或凭据。此获取策略不更改 QQ 或已保存的漫画下载方式，也不将代理下载静默改为直连。

默认并发 3、连接 8 秒、单次图片总等待 45 秒（含连接）、每页最多 3 个不同图片源且各试一次、无图片完成进展 150 秒停止、网络下载软预算 1800 秒，不计入 PDF 合成和上传。设置允许并发 1–5、连接 1–60 秒、图片总等待 1–300 秒、来源 1–6 个、无进展 1–1800 秒、网络预算 1–7200 秒；图片总等待不得小于连接等待。网页以分钟展示网络预算，保存到整数秒。“恢复推荐值”只改草稿，保存后生效。

初始漫画信息阶段另有 60 秒预算，单次 API 请求最多 20 秒，每个 API 请求最多两个域名。图片优先复用当前任务已成功来源，后续候选有界，不跨任务记忆。超时和停止依赖请求与原生工作线程检查点，不承诺到时立即强制结束；线程退出前仍占任务槽。进度公开页数、阶段、来源及停止原因，不公开代理密码、订阅内容或完整链接。

固定直接依赖见 `requirements.txt`：`jmcomic==2.7.10`、`img2pdf==0.6.3`、`websockets==17.4`、`aiohttp==3.14.5`、`qrcode==8.2`、`PyYAML==6.0.3`。基础镜像为 `python:3.12-slim`；HTML/CSS/JS 随镜像交付，无前端构建服务。Playwright 仅用于开发和 CI，普通测试 PDF 打包到 `/app/samples/test.pdf`。

源码与部署包使用公开文件白名单，不包含运行配置、QQ 登录状态、代理数据、下载目录或日志。基础镜像和传递依赖未做全量哈希锁定，重建仍可能有补丁或体积差异；部署使用固定发布标签。

验证分三层：Python 单元和本地 HTTP/WebSocket 集成覆盖边界；真实浏览器保留 HTTPS 网关回归并检查新下载/代理流程；Linux/Docker 的 `scripts/mihomo_smoke.py` 使用真实固定核心和受控 HTTP 节点，检查原生解析、自动选点、回滚与重启。浏览器的控制端替身不能代替真实核心检查，受控节点也不能代替用户订阅及 JM 上游验收。成品镜像另做网页启动、权限恢复和只读文件检查。

只有镜像发布及匿名拉取检查成功后才可宣布可拉取；只有用户部署环境的扫码、群选择、私聊/群文件、真实下载、代理与重建恢复验收成功后才可标为稳定版。旧版测试或公开状态不能代替新版验收。

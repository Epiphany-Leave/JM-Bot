# 独立 JM-Bot 的交付决策

统一管理页让用户只填一个管理密码，在同一网页完成 QQ、权限及文件测试。rc.3 增加下载控制与 NAS 独立代理，保留原有 AstrBot，不要求在 NAS 安装 Python、VPN GUI 或 Clash Verge。rc.3 镜像目前待发布；代码和测试方法不等于已通过真实 NAS 验收。

| 决策 | 原因与边界 |
| --- | --- |
| 一个项目、三个容器 | JM-Bot 提供网页和下载，NapCat 连接 QQ，Mihomo 处理可选的 JM 代理；无需模型或额外数据库 |
| 仅映射 `16099:8080` | NapCat 6099、OneBot 3001、Mihomo 控制和代理端口不发布到 NAS |
| 默认网络加独立 `proxy` 网络 | JM-Bot 与 NapCat 使用默认网络，JM-Bot 与 Mihomo 使用代理网络，NapCat 不加入后者；不设置 QQ 或 NAS 全局代理 |
| 不使用 TUN、主机网络、Docker socket | 不接管宿主网络，不授予代理管理 Docker 的能力 |
| 网页先健康，外部服务再启动 | JM-Bot 预写内部配置；网页健康不依赖 QQ 登录或代理联网，避免循环等待 |
| 一个用户管理密码 | 至少 12 字符；内部 OneBot、代理认证和控制口令自动生成并持久化，无第二个密码或手动 token |
| 五个目录持久化 | `data`、`napcat-config`、`qq-data`、`downloads`、`proxy-data`；配置和代理目录含私密口令与节点，备份不公开 |
| rc.2 升级完整替换 Compose | 新增服务、网络和挂载，不能只改镜像标签；保留密码、原端口和旧目录，再新增 `proxy-data` |
| 指定群默认全员可用 | 只有已选群生效；可改为群号和用户同时授权，私聊始终检查用户；空名单拒绝对应请求 |
| 权限热保存，网络设置空闲保存 | 白名单保存后对后续调用立即生效；下载设置和代理操作不能改变执行中任务的网络 |
| 默认直连，代理须显式保存 | 导入并测试连接后再切换并保存 Mihomo 模式；检测使用已保存模式，代理故障不静默回退直连 |
| 程序拥有 Mihomo 配置 | Clash YAML 仅保留节点；原端口、控制器、TUN、规则不生效；其他格式由核心原生解析，无外部转换服务 |
| 链接或文件导入，最大 2 MiB | 链接受阻可上传 `.yaml`、`.yml`、`.txt`；文件无更新链接时重新上传，不承诺所有 VPN 格式 |
| 节点事务式应用 | 核心接受且实际连接探测成功才保存；失败保留之前持久化配置；冷重启后重新验证健康 |
| Mihomo `metacubex/mihomo:v1.19.33` | 固定 `linux/amd64`，匹配目标 x86-64 NAS；无需电脑代理持续运行 |
| 全局单任务，无队列和跨任务续传 | 下载、合成、上传共用任务槽；重启不续传，上传未确认不自动重发 |
| 完整图片清单才合成 PDF | 缺页、损坏、停止或失败不发半本；清理失败任务图片，仅已生成但发送未确认的 PDF 留存 |
| 停止是协作式退出 | 网络阶段可停止，PDF 合成和上传不提供停止；底层请求及线程结束后才释放槽位，无硬 I/O 中断保证 |
| 任务目录 0755、PDF 0644 | NapCat UID/GID1000 可读取；NAS ACL 仍需实际发送 PDF 验证 |

默认并发 3、连接 8 秒、单次图片总等待 45 秒（含连接）、每页最多 3 个不同图片源且各试一次、无图片完成进展 150 秒停止、网络下载软预算 1800 秒，不计入 PDF 合成和上传。设置允许并发 1–5、连接 1–60 秒、图片总等待 1–300 秒、来源 1–6 个、无进展 1–1800 秒、网络预算 1–7200 秒；图片总等待不得小于连接等待。网页以分钟展示网络预算，保存到整数秒。“恢复推荐值”只改草稿，保存后生效。

初始漫画信息阶段另有 60 秒预算，单次 API 请求最多 20 秒，每个 API 请求最多两个域名。图片优先复用当前任务已成功来源，后续候选有界，不跨任务记忆。超时和停止依赖请求与原生工作线程检查点，不承诺到时立即强制结束；线程退出前仍占任务槽。进度公开页数、阶段、来源及停止原因，不公开代理密码、订阅内容或完整链接。

固定直接依赖见 `requirements.txt`：`jmcomic==2.7.10`、`img2pdf==0.6.3`、`websockets==17.4`、`aiohttp==3.14.5`、`qrcode==8.2`、`PyYAML==6.0.3`。基础镜像为 `python:3.12-slim`；HTML/CSS/JS 随镜像交付，无前端构建服务。Playwright 仅用于开发和 CI，普通测试 PDF 打包到 `/app/samples/test.pdf`。

源码与部署包使用公开文件白名单，不包含运行配置、QQ 登录状态、代理数据、下载目录或日志。基础镜像和传递依赖未做全量哈希锁定，重建仍可能有补丁或体积差异；NAS 使用固定发布标签。

验证分三层：Python 单元和本地 HTTP/WebSocket 集成覆盖边界；真实浏览器保留 HTTPS 网关回归并检查新下载/代理流程；Linux/Docker 的 `scripts/mihomo_smoke.py` 使用真实固定核心和受控 HTTP 节点，检查原生解析、自动选点、回滚与重启。浏览器的控制端替身不能代替真实核心检查，受控节点也不能代替用户订阅及 JM 上游验收。成品镜像另做网页启动、权限恢复和只读文件检查。

只有镜像发布及匿名拉取检查成功后才可宣布可拉取；只有用户 NAS 的扫码、群选择、私聊/群文件、真实下载、代理与重建恢复验收成功后才可标为稳定版。旧版测试或公开状态不能代替新版验收。

部署以仓库 [compose.yaml](../compose.yaml) 为准，操作见 [README](../README.md)，各版本实测证据见[验证记录](verification.md)。
